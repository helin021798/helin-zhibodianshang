# 直播电商文稿拆解

## 目标

从直播回放转写稿还原直播货盘、排品动线、逼单节奏和主推品话术，交付专业、直接、可复用且有证据约束的五模块报告。

## 开始前

1. 完整阅读 `references/analysis-rules.md`，按其中的证据、分品、定位、计时和转写纠错规则分析。
2. 完整阅读 `references/report-template.md`，严格按模板的模块顺序交付。
3. 确认已获得直播文稿。没有文稿时停止分析并请用户上传或粘贴。
4. 核对以下背景信息：
   - 直播间品类或行业；
   - 账号名称，可选；
   - 本场直播时长；
   - 用户已知的主推品，可选。
5. 将缺失项合并成一次简短询问。品类能从文稿可靠判断时可注明“根据文稿推断”并继续；时长缺失时按每分钟250个有效字估算；账号和已知主推品缺失不阻塞分析。

## 分析工作流

### 1. 检查文稿完整性

- 判断文稿是完整场次、节选还是疑似截断稿。
- 记录是否含可靠时间戳、说话人标记和商品名称。
- 文稿不完整时只分析可见范围，并在摘要和结论中标明范围，不外推整场表现。

### 2. 保守清洗转写稿

- 去除明显口头禅、机械重复和无关闲聊，但不要删除承担转场、铺垫或逼单作用的内容。
- 只修正能被上下文唯一确认的转写错误。
- 不擅自修正产品名、规格、价格、库存、优惠机制和功效表述；无法确认时标记“疑似转写错误”或“文稿中未明确”。

### 3. 建立产品出场台账

- 按首次出现顺序识别每个产品及其每次出场边界。
- 将同一产品的返场合并统计，同时保留每次返场的位置、前后产品和触发语境。
- 为价格、机制、卖点、定位和节奏判断保留短证据片段或位置标记。
- 需要确定字数和估算时长时，可对已分段文本运行 `scripts/text_metrics.py`；不能可靠分段时不要制造精确数字。

### 4. 判定货盘角色

- 综合讲解时长、返场频次、逼单力度、机制投入和价格功能判定福利品、次推品和主推品。
- 主推品最多两个。证据不足时标为“暂定”，并解释不确定性。
- 将角色定位写成分析判断，不把它伪装成主播或品牌方的官方定义。

### 5. 还原排品与逼单节奏

- 有原始时间戳时使用原始时间戳。
- 没有时间戳时，根据累计有效字数按每分钟250字估算，统一标注“估算时间点”。
- 识别产品的策略作用时，使用“推断承担拉停留/促转化/拉GMV等作用”的表达；没有在线、成交或GMV数据时不得声称实际效果已经发生。
- 针对最多两个主推品，按真实出现顺序拆解铺垫、价值塑造、价格锚定、亮价、紧迫感、库存施压、改价配合和售后兜底。

### 6. 整理与抽象话术

- 按时间顺序整理主推品话术，保留原意，不把整理稿扩写成文稿中不存在的新卖点。
- 给每段添加准确的类型标签；只有确有学习价值时才添加亮点评注。
- 从已出现的话术结构中抽象通用框架，区分固定步骤和需替换变量，并标注目的与建议时长占比。

### 7. 输出报告

严格依次输出：

1. 直播货盘总览；
2. 排品策略与节奏拆解；
3. 主推品话术整理；
4. 可复用话术框架；
5. 综合点评。

报告开头先用2至3句话概述品类、直播时长、产品数量和主推品。未知或估算信息必须就地标注。

## 交付前检查

- 每个价格、机制、主推品定位和策略判断是否能回到文稿证据。
- 是否把估算时间点、推断作用和事实信息明确区分。
- 是否误把ASR纠错写成已确认事实。
- 是否覆盖文稿中出现的全部可识别产品和返场。
- 是否只整理最多两个主推品。
- 是否完全排除投流和付费流量分析。
- 信息不足时是否明确写“文稿中未体现”，而非填充性分析。
- 点评是否具体到动作、话术或排品策略；没有明显问题时不硬挑毛病。

任一检查不通过时，先修正报告再交付。
