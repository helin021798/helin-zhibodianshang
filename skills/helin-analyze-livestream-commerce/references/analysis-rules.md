## 1. 证据等级与引用格式

将报告内容分为四类，并在措辞上保持区别：

- **文稿事实**：产品名、主播明确说出的价格、规格、机制、库存口播、承诺和原始时间戳。注意：“库存只剩 3 单”是“主播口播了库存只剩 3 单”这一事实，不是库存本身的事实。
- **数据对照**：仅在用户提供直播数据或宿主数据工具返回数据时使用。写明数据来源和时间粒度，只陈述时间上的相关性。
- **分析判断**：产品角色、排品策略、逼单环节和话术作用。写明判断依据。
- **效果推断**：拉停留、促转化、拉GMV等目的。没有数据时只能写“推断承担……作用”，不能写成实际结果。

价格、优惠、库存和功效信息发生冲突时，逐处列出冲突，不替主播选择一个“正确版本”，标记“文稿中口径不一致”。

### 统一引用格式

全报告使用同一种引用标记，便于读者回查：

`〔P2·R2｜01:02:32｜“最后只能加一单”〕`

- 第一项：出场编号，与台账一致。`P` 为商品，`N` 为非商品段；首次出场只写 `P2`，`P2·R2` 表示第 2 次出场；
- 第二项：原始时间戳，或带“约”字的估算时间；
- 第三项：可选，不超过 20 字的原话短引。

## 2. 文稿完整性与ASR纠错

先判断文稿属于：完整直播、明确节选、开头或结尾疑似截断、无法判断完整性。节选或截断时只分析可见范围，不外推整场。文件名、标题、文件头日期等元信息互相矛盾时，在摘要中列出，以标题或用户说明为准。

截断稿中，首讲发生在截断前的商品（线索如“刚才说到的”“先按顺序返场”）标注“首讲不可见”：角色判定时 A 项不适用，按其余信号判定；台账仍按可见顺序编号，在动线中注明“实为返场”；逼单循环只拆可见部分，并在表头注明。首讲开头被截掉、但亮价或上链仍可见的商品属于“部分可见”，A 项照常适用，注明时长偏低。

只在上下文能够唯一确定时修正错字。例如品牌名在多处稳定出现，仅一处为同音错字时可以统一。以下信息不得凭经验纠正：

- 产品名和品牌名；
- 数量、规格、价格、折扣和库存；
- 成分、认证、产地和功效；
- 售后承诺与适用人群。

不能确认时保留原意并写“疑似转写错误”。同一品牌或品名出现多种转写时，报告按“文件名或标题 > 讲解中最完整、最像正式品名的写法 > 出现次数最多的写法”选一个作为统一指代，首次出现时括注其他写法，例如“仅三（口播转写另作景三/锦三/井三）”；这是指代统一，不是事实纠错。不要为了让话术通顺而添加文稿中不存在的卖点、论据或承诺。多说话人文稿要区分主播、助播、运营、品牌方，改价、加库存、踢单常由运营或助播发起，归属到正确的人。

## 3. 长文稿处理流程

直播文稿常有数万字，一次性读完再凭印象写报告，是数字和返场出错的主要来源。按以下顺序处理：

1. 运行 `outline` 得到分段目录（段号、时间、说话人、字数、开头预览）和实测语速。
2. 运行 `signals` 得到憋/卡/踢/促/上链/价格/售后的命中分布，作为定位线索。**命中不等于动作成立。**
3. 按顺序分块通读全文（每块约 5000–8000 字），边读边记录：产品切换点、上链/放单点、循环环节、用户问题、价格与机制口径、合规风险句。不要跳读中段。
4. 把产品与非商品段边界写成边界文件，运行 `ledger` 生成出场台账；检查“未归属段”和“重叠段”，未归属段要么补边界，要么在报告中说明是闲聊或无法归类。
5. 报告中的字数、时长、出场次数、占比一律以台账为准，不另行心算。

脚本无法运行时（无 Python 或文稿不是文本），照常分析，但只给“约X分钟”级别的区间估算，并在摘要中注明“未经脚本计量”。

## 4. 产品边界和返场识别

综合下列信号识别新品开始：

- 明确说出新产品名、品类或规格；
- 出现“下一个”“换一个”“来看这款”等转场语；
- 价格、赠品或库存机制整体重置；
- 卖点、使用场景和人群发生稳定切换；
- 上链接、改链接或报机制时指向另一产品或另一链接号。

不要把同一产品的不同规格、赠品或套装机械拆成多个产品。只有主播明确作为独立链接或独立价格机制销售时才分开。

同一产品的独立链接变体（如组合装与纯洗版）如果讲解交错、无法按连续段落切开，合并为一个编号，在价格/机制列分别写清各链接；能切开时分开编号。

同一产品离场后再出现，按以下标准判定：

- 持续 ≥1 分钟，且含重新亮价、报机制或逼单动作 → 记为返场；
- 持续 ≥1 分钟，只答疑不报价 → 记为返场，在动线中标“答疑返场”；
- 不足 1 分钟的顺带提及、比较或回答一句评论 → 不单独记录。

同时涉及多个商品的段落（如整套护肤演示、下播汇总）记为非商品段 N，在动线的衔接列写明涉及哪些商品。转场语的引用编号跟随它在台账中所属的段落。

## 5. 产品角色判定

先在台账上逐项核对以下六项信号，再做**综合判断**。信号是检查清单，不是计分器：报告中写明每个商品满足哪几项，以及最终判断的理由。

| 信号 | 说明 |
|---|---|
| A 时长 | 累计讲解时长居前，或明显高于商品时长中位数 |
| B 返场 | 出场 ≥2 次，或占据开场后、整点等关键时段 |
| C 循环 | 至少走出一轮含真实“卡单”或“踢单”的逼单循环（渠道稀缺叙事不算，见第 8 节） |
| D 机制 | 赠品、套装、改价、售后说明的层次明显多于多数商品；人人都有多档赠品时，只计最突出的一两个 |
| E 施压 | 针对该商品反复强调本场库存、名额、限时或运营配合；“满赠早上凑”这类不针对单品的场级促单不计入任何单品，在动线中单列 |
| F 自定性 | 主播或品牌方针对单个商品明确说“今天的核心/主推/最值得入”或“福利品/引流款”；多个商品并列的“今天必入清单”不算 |

判定要点：

- **主推品**：通常满足 A 加其余至少两项。最多两个；第三个强候选标“强次推”。
- **时长接近时不让 A 一票定案**：前几名时长差距在 10% 以内时，A 视为并列，由 B–F 和客单价、背书投入决定。
- **首讲不可见的商品**：A 不适用，B–F 中满足至少三项时，可判为“主推（依据可见返场）”。
- **自定性与信号冲突时**：两者都写出来。信号明显支持另一个角色时按信号判定并说明理由；信号不足以推翻时尊重自定性。例如被称为“福利品”的商品时长居前，可写“以福利价切入的强次推/主推”，并说明依据。
- **福利品**：被称为秒杀、福利、宠粉、引流款，或低价短讲、快速过款且价格本身是最大卖点。不能只凭讲解时间短判定；客单不低却被称为“福利”的，写明“名为福利，实为限量收口品”这类判断。
- **次推品**：有相对完整的讲解和转化诉求，但不满足主推条件，也不以低价引流为核心。
- **其他**：形象款/锚点款（高价展示用于对比，几乎不逼单）、凑单承接品、下场预告品。非独立售卖的赠品写在所属商品的机制里，不单独占行。

不能只凭产品价格高判定主推品。全场只有一个可售商品时，直接说明“单品专场”，不需要套用三类结构。

## 6. 字数、时间与语速校准

“有效字数”口径：每个中日韩文字计 1，连续英文或数字词组计 1，标点、空白、说话人标签和时间戳不计。

语速按以下优先级确定，并在摘要中写明采用哪一种：

1. **文稿有原始时间戳**：直接使用时间戳计算时长和时间点，语速由脚本实测。
2. **无时间戳但用户提供了实际总时长**：语速 = 总有效字数 ÷ 实际分钟数，再据此估算各段时间。
3. **两者都没有**：按 250 字/分钟估算，所有时间写“约”，并提示偏差可能较大。

为什么不能一律用 250：带货直播实测语速常在 280–330 字/分钟，转写稿又会漏掉音乐、等待和副播的话，固定用 250 会把整条时间线向后拉长 20%–30%。

表格中时长保留 1 位小数或取整，不足 1 分钟写“<1分钟”。不要输出伪装成原始记录的精确秒数。

## 7. 排品作用与策略命名

判断单品或非商品段作用时观察：

- 开场低门槛和高互动召唤：推断拉停留或激活互动；
- 完整价值塑造和强逼单循环：推断承担核心转化；
- 高客单或大套组反复返场：推断承担拉GMV；
- 主推后快速低价款：推断回拉节奏或承接未成交用户；
- 次推品连接两个强促单段：推断承担节奏过渡；
- 福袋、抽奖、亮灯牌、预约：推断承担留人、拉互动或蓄积下一场流量。

策略模型必须从实际顺序抽象，使用“功能+阶段”命名，例如：

`开场预告憋单 → 福利炸场 → 主推循环×3 → 抽奖回拉 → 主推返场 → 下场预告`

不要套用任何预设节奏模板后倒推文稿。

## 8. 逼单节奏识别

以 `helin-method.md`「憋单—卡单—踢单—促单循环」一节的**憋单—卡单—踢单—促单**循环为主框架，按轮次记录。

**轮次切分：** 首轮从该商品开讲起算；以“上链接/放单”为锚点，下一次锚点前的内容归入本轮。没有上链口播的商品以首次亮价为锚。返场中只是重新亮价、确认链接号、限时涨价或答疑，没有重新上链或放单的，不算新一轮，记为该返场的促单或答疑。

**卡单与稀缺叙事要分开：** 卡单指本场链接已上后，强调**本场**库存、名额、放单数（“这一轮就 30 单”“只剩 3 单”）。“全网断货”“库存都挪给我们了”“只有我这儿有”属于渠道稀缺叙事，标【稀缺叙事】，作为价值塑造的子动作，不计为卡单。同一句话两者兼有时（“品牌断货，只给我们一点超额”），本场额度部分计卡单，渠道部分另标稀缺叙事。

循环内部可能出现的子动作，作为补充标签标注：

- 痛点或场景铺垫；
- 产品与卖点说明、证据或价值塑造；
- 日常价、竞品价、官网价或组合价锚定；
- 首次亮价、上链接、报链接号；
- 赠品、满减、券或套装机制；
- 售后、退换、试用或风险兜底；
- 渠道稀缺叙事；
- 下单指令和重复报机制。

没有出现的环节不要补齐。每个主推品输出一条“循环节奏公式”，反映本场真实动作，例如：

`憋单（扣1+还没上）→ 亮价上链 → 卡单（断货口播）→ 踢单（加1单）→ 促单（赠品加码）｜单轮约9分钟×3轮`

小红书场次改拆“信任转化链”，见 `helin-method.md`「三平台适配」一节。

## 9. 话术整理与框架抽象

模块三是“基于原文的整理稿”，不是重新创作：

- 保留原有信息和出现顺序；
- 合并机械重复，但保留有策略意义的重复逼单；
- 删除无关闲聊和口头禅；
- 用【类型标签】标注每段功能，循环环节优先使用【憋单】【卡单】【踢单】【促单】；
- 只有段落确有亮点时使用“➤”点评；
- 含合规风险的原话照实整理，在段尾标“⚠”并写明风险类型。

模块四才进行框架抽象。每个环节必须包括：环节名称、目的、建议时长占比、可直接套用的句式骨架、用【此处填入：XXX】标记的变量、合规提示。建议时长占比是给使用者的建议值，以本场实测比例为参照再做调整，总和应为 100%，或说明区间会因产品复杂度浮动。

### 篇幅预算

- 模块三：每个主推品整理稿控制在 800–1500 字，挑最有代表性的一轮循环完整整理，其余轮次只写差异；
- 模块二动线：返场约 10 次及以上，或多品频繁交替返场时，按“阶段”归并，不逐条罗列；循环表可逐轮列出，但每格只写要点；
- 全报告有效字数通常 6000–12000 字（约合 1–2 万字符）。超出时先删重复描述，不删证据。

## 10. 合规标注

直播话术里常见违规表达。模块三照实记录并标 ⚠，模块四**不得**把它们沉淀为可复用句式，必须给出合规替换写法。重点识别：

| 风险类型 | 常见表达 | 框架中的处理 |
|---|---|---|
| 极限词与绝对化 | 最、第一、顶级、全网最低、史上最、国家级 | 改为可证实的具体描述，如“本场到手价 X 元” |
| 价格比较无依据 | 原价、官网价、专柜价、“别处卖 XXX” | 标注“需有真实成交价或公示价依据” |
| 虚构稀缺 | 只剩 X 单、全网断货、库存挪给我们、名额告急 | 标注“仅在真实库存/名额下使用” |
| 功效与医疗宣称 | 治疗、根治、消炎、药用、减肥 X 斤、对 X 病有效 | 普通食品、化妆品、器械按其备案范围表述，不写疗效 |
| 绝对化承诺 | 假一赔十、无效全额退、永久保修 | 标注“需与真实售后政策一致” |
| 诱导互动 | 不扣 1 不上链接、长时间不开链接只要互动 | 抖音等平台对此有治理规则，提示以平台现行规则为准 |
| 站外导流 | 加群、接龙、加微信、留地址领赠品 | 抖音、小红书限制严格；视频号依托微信生态相对开放，但仍有规则。一律提示以平台现行规则为准 |

合规提示是风险提醒，不是法律意见；平台和行业规则以其最新公示为准。

## 11. 禁止事项

- 不分析投流、付费流量、投产比或广告策略。
- 没有数据时，不从话术反推真实销量、在线人数、GMV或转化率。
- 不把主播宣称自动视为客观事实。
- 不编造产品功效、认证、口碑、库存和售后政策。
- 不为凑齐模块而填写无证据内容。
- 不把“讲得多”等同于“卖得好”。
- 不把小红书场次“缺少憋卡踢循环”判为缺陷。
- 文稿中出现的观众昵称、手机号、地址等个人信息不写入报告。
