# 五模块直播拆解报告模板

严格保持模块顺序。表格无法可靠填写的字段写“文稿中未明确”，不要删除字段。标注“条件”的小节只在条件满足时输出，不满足时整节省略，不写空表。引用一律使用 `〔编号｜时间｜“短引”〕` 格式。语气和密度对照 `example-report.md`。

# 【账号/场次】直播拆解报告

> 文稿：{文件名或“用户粘贴”} ｜ 平台：{视频号/抖音/小红书/未明确} ｜ 时间口径：{原始时间戳/按X字每分钟估算} ｜ 数据：{无，仅文稿/用户提供的XX数据} ｜ 方法：河林直播拆解方法论

## 全文摘要

用 2 至 4 句话说明：

- 品类或行业（跨品类写“主品类为主，兼有某某”）、平台、直播时长（注明实际或估算）；
- 可识别商品数量和非商品段的主要类型；
- 判定的主推品及其主要依据；
- 本场最核心的打法一句话；
- 如为节选或截断稿，立即说明分析范围。

定位列在“暂定”时写“暂定主推品”。时长与字数取自出场台账。

### 关键判定依据

只对主推品、存在争议的定位和重要价格机制补充证据，写明满足了 A–F 中哪几项信号，以及综合判断的理由：

- **P1 产品名**：满足 A/B/E/F，C 缺失。证据〔P1·R2｜00:42:10｜“……”〕。判断理由：……

### 货盘结构小结

一段话说明：共几个品，各角色几个；整体搭配逻辑；价格带分布；判断中有哪些不确定项。

非商品段（开场预告、抽奖、福袋、亮灯牌、下场预告等）用 N 编号进入动线。返场超过 10 次时按阶段归并。没有数据时，作用列保持“推断”口径。

### 2.2 排品策略归纳

**一句话策略模型：** 开场预告憋单 → …… → 下场预告

随后解释：为什么这样命名；各阶段如何衔接；哪些是文稿事实、哪些是推断。`helin-method.md` 提供直播节奏参照时，说明本场在哪里吻合、在哪里刻意偏离。

小红书场次将本节标题改为“主推品信任转化链”，表头换为：痛点/场景、讲解与证据、机制与利益点、预期管理与售后、下单指令。

|---:|---|---:|---|---|---|---|---|
| 1 |  |  | 要点+〔引用〕 | 要点 | 文稿中未体现 | 要点 |  |

**循环节奏公式：** 憋单（……）→ …… ｜单轮约X分钟×N轮

**节奏判断：** 对照 5–15 分钟基准，说明快慢、哪一环最强、哪一环缺失，以及缺失的可能用意。结合平台说明这种节奏是否匹配（见 `helin-method.md`「三平台适配」一节）。

## 模块五：综合点评

### 最值得学习的亮点

只写 1 至 3 个，每个按以下结构：

1. **具体动作/话术/策略**：发生了什么。
2. **为什么有效或值得借鉴**：解释机制；有数据对照时引用数据，没有时写“推断”。
3. **文稿依据**：〔引用〕。
4. **可复制边界**：什么平台、品类、客单价下适用，什么情况下不应照搬。

### 明显可优化之处

有证据才写。每项按“问题表现 → 文稿依据 → 可能影响 → 具体改法”展开。用户高频提问未被正面回应、循环中断后没接回、合规风险句是优先关注项。没有明显问题时直接写：

“基于现有文稿，未发现证据充分且值得单独提出的明显问题。”

### 结论

一段高密度结论：这场直播最核心的打法、最值得迁移的能力、分析受限于哪些缺失信息，以及**补充哪类数据可以验证本报告的推断**。

如用户要据此策划下一场直播，在结论后加一句：可将本报告交给直播策划类技能（如 `helin-livestream-planning-master`）作为“上一场复盘”输入。
